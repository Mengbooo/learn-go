# 07 缓存 Redis 与性能优化任务文档

## 1. 文档目标

本阶段的核心不是“把所有数据都放进 Redis”，而是学会判断什么时候该缓存、怎么缓存、缓存会带来什么新问题，以及如何在小型后端项目中做最实用的性能优化。

## 2. 学习结果

- 能识别适合缓存和不适合缓存的场景。
- 能使用 Redis 实现基础缓存、限流、任务状态存储。
- 能理解缓存一致性和热点风险。

## 3. 知识层次拆解

### 3.1 Redis 基础能力

你需要掌握 String、Hash、List、Set、Sorted Set、TTL。

扩展说明：

- 不同数据结构服务不同业务形态，例如计数器、状态缓存、排行榜、集合去重。
- TTL 决定缓存生命周期，设置过短会频繁回源，过长会导致脏数据风险增大。

### 3.2 缓存策略

你需要掌握 Cache Aside 及其读写流程。

扩展说明：

- 小项目优先使用 Cache Aside：读时先查缓存，未命中再查库并回填；写时先写库再删缓存。
- “更新缓存”看起来直接，其实更容易引入脏写和一致性问题。

### 3.3 缓存风险

你需要掌握缓存穿透、击穿、雪崩和一致性问题。

扩展说明：

- 穿透是查不存在的数据，击穿是热点 key 瞬时失效，雪崩是大量 key 同时失效。
- 这些问题本质上都会把压力重新打回数据库，因此不能只从功能角度看缓存。

### 3.4 限流与分布式锁基础

你需要掌握基于 Redis 的基础限流思路和锁的适用边界。

扩展说明：

- 限流很适合登录接口、验证码接口、公开查询接口。
- 分布式锁不是默认方案，只在跨实例竞争且业务确实需要互斥时使用。

### 3.5 性能优化判断

你需要建立一个原则：

- 先确认瓶颈，再决定是否引入缓存。

扩展说明：

- 很多项目还没形成真实流量就过早引入缓存，反而增加维护复杂度。
- 你要先看访问频率、变更频率、一致性要求、数据库压力和实际响应耗时。

## 4. 任务拆解

### 任务 1：接入 Redis

要求：

- 本地启动 Redis。
- 在 Go 服务中完成连接和基本读写。

目标：

- 建立 Redis 的工程接入能力。

### 任务 2：实现热点列表缓存

要求：

- 例如书签列表、公开配置或用户信息摘要缓存。

目标：

- 训练 Cache Aside 基本流程。

### 任务 3：实现登录限流

要求：

- 按 IP 或账号维度做短期限流。

目标：

- 将 Redis 用在真正有业务价值的地方。

### 任务 4：分析缓存收益与风险

要求：

- 选择一个接口，说明为什么要缓存、缓存键怎么设计、TTL 怎么定。

目标：

- 形成性能优化的判断力，而不是机械套方案。

## 5. 产出物

- Redis 本地接入配置。
- 一到两个缓存案例。
- 一个基础限流中间件或限流逻辑。

## 6. 验收标准

- 能解释某个接口为什么适合或不适合缓存。
- 能说明缓存 key 和 TTL 的设计理由。
- 能解释写后删缓存而不是直接更新缓存的原因。
- 能识别缓存一致性和热点失效风险。
