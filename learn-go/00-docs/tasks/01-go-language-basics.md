# 01 Go 语言基础任务文档

## 1. 文档目标

本阶段的目标不是背语法，而是建立你写 Go 后端代码时最基本的表达能力。完成后你应该能看懂常见 Go 代码、写出结构清晰的小程序，并且理解 Go 和 JavaScript / TypeScript 在建模方式上的差异。

## 2. 学习结果

完成本阶段后，你需要达到下面三个结果：

- 能独立写出中小型命令行工具和简单业务逻辑。
- 能解释常见 Go 语法背后的设计意图，而不是只会照抄。
- 能识别新手最容易写错的地方，例如零值、切片扩容、变量遮蔽、接口误用。

## 3. 知识层次拆解

### 3.1 变量、常量与作用域

你需要掌握 `var`、`:=`、`const`、`iota`、零值、作用域和变量遮蔽。

扩展说明：

- `var` 适合需要显式类型、包级变量、零值初始化的场景。
- `:=` 适合函数内部的局部变量快速声明，但容易和已有变量混用造成遮蔽。
- 零值是 Go 非常重要的设计基础，很多结构在未手动初始化时也能以可预测方式工作。
- `iota` 常用于枚举型常量，但要注意它只是常量生成器，不自带类型语义。
- 变量遮蔽是初学者高频 bug 来源，尤其是在 `if err := ...; err != nil` 和循环中。

### 3.2 基础类型与类型转换

你需要掌握 `bool`、`int`、`int64`、`float64`、`string`、`byte`、`rune` 以及显式类型转换。

扩展说明：

- `int` 通常用于一般计数和索引；涉及数据库 ID、时间戳、跨服务数据交换时更常用 `int64`。
- `float` 不适合做精确金额计算，后端里要特别警惕精度问题。
- `byte` 更偏向原始数据和 I/O，`rune` 更偏向 Unicode 字符语义。
- Go 不做隐式数值转换，这会增加一点书写量，但可以减少很多隐藏错误。

### 3.3 复合类型

你需要掌握数组、切片、`map`、结构体、结构体标签、JSON 标签和嵌入结构体。

扩展说明：

- 切片是后端代码里最常用的数据结构之一，重点要理解 `len`、`cap` 和扩容行为。
- `map` 查询不存在的键会返回零值，因此业务代码里经常需要配合 `comma-ok` 模式判断是否存在。
- 结构体是 Go 业务建模的核心手段，标签会直接影响 JSON 编解码和数据库映射。
- 嵌入结构体常用于复用字段或能力，但过度嵌入会让模型边界变得不清晰。

### 3.4 控制流与函数

你需要掌握 `if`、`switch`、`for`、`range`、多返回值、可变参数、匿名函数、闭包。

扩展说明：

- Go 用 `for` 统一表达循环，不需要额外的 `while`。
- 多返回值和显式错误返回是 Go 后端的主流风格，后续几乎每层都会用到。
- 闭包可以提升表达力，但在循环中捕获变量时要特别谨慎。

### 3.5 指针、方法与接口

你需要掌握指针接收者、值接收者、方法、接口、类型断言、`type switch`。

扩展说明：

- Go 指针主要用于修改原对象、避免大对象拷贝、表达可选状态，不是为了做复杂指针运算。
- 值接收者适合只读、轻量结构；指针接收者适合需要修改状态或避免复制的情况。
- 接口是隐式实现，这使得 Go 在依赖抽象和测试替身上很灵活，但也要求你控制接口粒度。
- 接口应该围绕“行为”设计，而不是为了抽象而抽象。

### 3.6 错误处理与泛型基础

你需要掌握 `error`、错误包装、错误比较、泛型函数、泛型类型、类型约束。

扩展说明：

- Go 的错误处理强调显式控制流，不依赖异常机制。
- `errors.Is` 和 `errors.As` 是后续做分层错误处理的关键工具。
- 泛型适合通用工具和通用容器，不适合把简单业务逻辑抽象得过度复杂。

## 4. 任务拆解

### 任务 1：语法速写练习

要求：

- 写一组小函数，分别覆盖变量、函数、结构体、方法、接口、错误处理。
- 每个函数只解决一个小问题，避免一上来写大程序。

目标：

- 把语法从“看懂”变成“能写”。

### 任务 2：CLI Todo 工具

要求：

- 支持新增、列出、完成、删除 Todo。
- 数据先存内存，后续可升级为文件存储。

目标：

- 练习结构体、切片、方法、错误返回和命令行参数解析。

### 任务 3：文件统计工具

要求：

- 统计目录下文件数量、总大小、后缀分布。

目标：

- 练习 `os`、`filepath`、`map`、错误处理和格式化输出。

### 任务 4：JSON 配置读取器

要求：

- 从 JSON 文件读配置，映射到结构体，校验关键字段。

目标：

- 练习结构体标签、JSON 编解码、默认值处理。

### 任务 5：并发 URL 检测器

要求：

- 并发请求一组 URL，输出状态码和耗时。

目标：

- 为后续并发章节打基础，提前感受 goroutine、channel、超时控制。

## 5. 产出物

- 一个 `examples/` 或 `practice/` 目录。
- 至少 3 个可运行的小程序。
- 一份自己的语法易错点笔记。

## 6. 验收标准

- 能解释 `slice` 和 `array` 的区别。
- 能解释 `map` 不存在键时的行为。
- 能说明什么时候用指针接收者。
- 能写出带错误返回的函数调用链。
- 能写出结构清晰、命名自然的 Go 小程序。

## 7. 下一阶段衔接

当你已经可以比较自然地写出小程序，并且不再被基础语法频繁卡住时，就进入 `02 Go 工具链与工程规范`。下一阶段重点不再是“语法能不能写”，而是“代码怎么组织、怎么构建、怎么检查、怎么跑测试”。
