# 04 数据库 SQL 事务与索引任务文档

## 1. 文档目标

本阶段的核心是让你从“接口能跑”升级到“数据模型正确、查询稳定、写入可靠”。数据库是后端能力的分水岭，必须从一开始建立正确认知。

## 2. 学习结果

- 能设计基础表结构并解释字段和索引选择。
- 能写常见 SQL 并接入 Go 服务。
- 能判断哪些业务操作需要事务，哪些不需要。

## 3. 知识层次拆解

### 3.1 表设计基础

你需要掌握主键、外键、唯一约束、非空约束、时间字段、软删除字段。

扩展说明：

- 表设计不是把前端字段原样搬进数据库，而是要围绕数据关系和查询模式来设计。
- `created_at`、`updated_at`、`deleted_at` 往往决定后续运维、审计和数据恢复能力。
- 唯一约束不仅是业务规则，也是数据质量保护机制。

### 3.2 SQL 查询能力

你需要掌握 `SELECT`、`INSERT`、`UPDATE`、`DELETE`、条件过滤、排序、分页、`JOIN`。

扩展说明：

- SQL 是后端工程师必须掌握的基础语言，不能完全依赖 ORM 屏蔽。
- 你要能从接口需求反推 SQL，而不是先写一堆模型再猜数据库怎么查。
- 列表查询、搜索、分页和关联查询是最常见的真实场景。

### 3.3 索引设计

你需要掌握普通索引、唯一索引、联合索引和索引失效的常见原因。

扩展说明：

- 索引不是越多越好，它会提升查询速度，也会增加写入成本和存储成本。
- 设计索引时要先看查询条件和排序方式，而不是凭直觉加索引。
- 你需要能解释“为什么这个字段要建索引”“这个联合索引为哪类查询服务”。

### 3.4 事务与一致性

你需要掌握事务边界、提交、回滚、隔离级别和典型事务场景。

扩展说明：

- 事务的核心价值是把多步操作变成一个原子动作。
- 不是所有写操作都需要事务，但涉及多表一致性或跨步骤约束时通常需要。
- 事务太大也会带来锁竞争和性能问题，因此边界要尽量清晰。

### 3.5 数据库接入方式

你需要掌握 `database/sql`、`pgx` 或 `sqlc` 的基本使用方式。

扩展说明：

- 推荐先学手写 SQL，再逐步引入 `sqlc` 这类工具提高类型安全和维护性。
- 连接池、查询超时、错误处理都是接入层必须关注的点。

## 4. 任务拆解

### 任务 1：为 Bookmark 设计表结构

要求：

- 设计 `users`、`bookmarks`、`tags`、`bookmark_tags`。
- 补齐主键、外键、唯一约束和必要索引。

目标：

- 训练关系建模和查询前置思考能力。

### 任务 2：编写 Migration

要求：

- 提供初始化和回滚脚本。
- 保证本地能重复执行。

目标：

- 建立结构变更可追踪、可回放的意识。

### 任务 3：接入真实数据库

要求：

- 将现有 API 从内存存储切换到 PostgreSQL。
- 至少完成新增、详情、列表、删除链路。

目标：

- 打通 HTTP 层到数据库层的真实服务流程。

### 任务 4：实现事务场景

要求：

- 例如创建书签时同时写标签关联。
- 失败时保证整体回滚。

目标：

- 建立事务编排意识。

## 5. 产出物

- 一份数据库设计文档。
- 一组 migration 文件。
- 一版接入 PostgreSQL 的 API。

## 6. 验收标准

- 能解释每个表和字段的设计原因。
- 能解释每个索引服务的查询场景。
- 能说明某个创建流程为什么需要事务。
- 能运行 migration 完成建表和回滚。

## 7. 下一阶段衔接

数据库接入完成后，下一步要进入 `05 项目结构 / 分层架构 / 业务建模`，解决代码越写越多后如何保持清晰边界的问题。
