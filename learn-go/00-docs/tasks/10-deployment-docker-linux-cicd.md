# 10 部署 Docker Linux 与 CI CD 任务文档

## 1. 文档目标

本阶段要解决“代码写好了，怎么稳定跑起来”的问题。你需要掌握容器化、本地多服务编排、服务器部署和最小持续集成流程。

## 2. 学习结果

- 能为 Go 服务编写基础生产可用 Dockerfile。
- 能通过容器编排启动应用、数据库、Redis 等依赖。
- 能建立最小 CI 流程，保证提交后自动检查。

## 3. 知识层次拆解

### 3.1 Linux 与环境变量

你需要掌握常见命令、进程、端口、文件权限、环境变量注入。

扩展说明：

- 后端部署离不开 Linux 基础，哪怕你主要使用 Docker，也要能排查进程和网络问题。
- 环境变量是配置注入的基本手段，数据库地址、密钥、端口都应通过配置管理。

### 3.2 Dockerfile

你需要掌握多阶段构建、工作目录、构建产物复制、启动命令。

扩展说明：

- Go 服务很适合做多阶段构建，既能减小镜像体积，也能减少不必要依赖进入运行环境。
- Dockerfile 的目标不是“能 build 成功”，而是“适合长期交付和部署”。

### 3.3 Docker Compose

你需要掌握多服务编排、网络、卷、环境变量文件。

扩展说明：

- 本地开发环境经常需要 Go API、PostgreSQL、Redis 同时启动。
- `docker-compose` 的价值是降低环境搭建门槛，让项目更容易复现。

### 3.4 健康检查与运行稳定性

你需要掌握 `/healthz`、`/readyz`、日志输出到 stdout、重启策略。

扩展说明：

- 健康检查让容器平台和运维系统知道服务是否活着、是否准备好接流量。
- 日志输出到 stdout 更容易被容器平台和日志系统采集。

### 3.5 CI/CD 基础

你需要掌握持续集成的最小流程：

- 拉代码
- 安装依赖
- 格式检查
- 跑测试
- 构建镜像或产物

扩展说明：

- 早期先把 CI 做好，比一上来追求全自动发布更重要。
- CI 的价值是防止明显问题进入主分支，而不是替代本地开发习惯。

## 4. 任务拆解

### 任务 1：编写 Dockerfile

要求：

- 为当前 Go 服务提供多阶段构建镜像。

目标：

- 让服务具备标准化运行形态。

### 任务 2：编写本地编排配置

要求：

- 至少包含 API、PostgreSQL、Redis。

目标：

- 实现一键启动开发环境。

### 任务 3：增加健康检查

要求：

- 提供基础存活和就绪检查接口。

目标：

- 为部署和监控打基础。

### 任务 4：接入 CI

要求：

- 自动执行格式检查、测试和构建。

目标：

- 让质量门槛进入自动流程。

## 5. 产出物

- 一份 Dockerfile。
- 一份 `docker-compose` 配置。
- 一套最小 CI 配置。

## 6. 验收标准

- 项目可以一键启动依赖环境。
- 镜像能稳定构建并运行。
- 服务有健康检查端点。
- 代码提交后可以自动执行基本校验。
