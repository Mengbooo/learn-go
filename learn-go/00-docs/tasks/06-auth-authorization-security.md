# 06 认证 鉴权与安全任务文档

## 1. 文档目标

本阶段要让你的后端具备真实用户系统能力。你不仅要实现“能登录”，还要理解谁能访问什么资源、令牌如何失效、接口哪里容易被攻击。

## 2. 学习结果

- 能实现注册、登录、鉴权和基础权限控制。
- 能避免常见安全错误，例如明文密码、越权访问、无过期 JWT。
- 能把认证和授权放在合适的层次实现。

## 3. 知识层次拆解

### 3.1 认证与鉴权的区别

你需要先分清：

- 认证是“你是谁”。
- 鉴权是“你能做什么”。

扩展说明：

- 很多项目登录做完了，但资源访问控制没做好，本质上就是只做了认证没做鉴权。
- 这两件事常常配合出现，但职责不同，实现位置也不同。

### 3.2 密码与登录

你需要掌握密码哈希、用户注册、密码校验、登录失败处理。

扩展说明：

- 密码永远不能明文存储。
- `bcrypt` 或 `argon2` 的核心价值不是“加密”，而是提高暴力破解成本。
- 登录失败次数过多时要有基础限流或封禁策略。

### 3.3 Token 与会话

你需要掌握 JWT、Access Token、Refresh Token、过期策略、撤销策略。

扩展说明：

- Access Token 生命周期应相对较短，降低泄露后的风险。
- Refresh Token 不是永远有效的万能钥匙，最好具备撤销能力。
- 你要清楚 token 校验是在中间件做，权限判断通常在业务层做。

### 3.4 权限模型

你需要掌握基础 RBAC。

扩展说明：

- 小项目可以先从 `user` / `admin` 两级角色做起。
- 资源级权限同样重要，例如“普通用户只能访问自己的书签”。
- 角色只是粗粒度能力，资源归属才是很多业务越权问题的关键。

### 3.5 常见安全风险

你需要掌握 SQL 注入、CORS、CSRF、XSS 基础、敏感配置管理、审计日志。

扩展说明：

- 后端最常见的安全问题往往不是高深攻击，而是基础边界没处理好。
- 敏感配置不能进入 Git，错误响应也不要泄露内部实现细节。
- 上传文件、第三方回调、公开接口都属于高风险入口。

## 4. 任务拆解

### 任务 1：实现注册与登录

要求：

- 用户注册时做密码哈希。
- 登录时进行密码校验并签发 token。

目标：

- 打通用户系统基础能力。

### 任务 2：实现认证中间件

要求：

- 解析 token。
- 将 `user_id`、`role` 注入上下文。

目标：

- 建立“请求身份”在服务中的传递机制。

### 任务 3：实现资源级权限控制

要求：

- 普通用户只能操作自己的资源。
- 管理员接口只允许管理员访问。

目标：

- 从“能识别身份”升级为“能控制访问范围”。

### 任务 4：补充基础安全策略

要求：

- 登录失败限流。
- 敏感配置走环境变量。
- 审计关键登录和管理操作。

目标：

- 为服务上线建立最小安全防线。

## 5. 产出物

- 一版带用户系统的 API。
- 认证中间件和权限校验逻辑。
- 一份安全风险清单。

## 6. 验收标准

- 密码不明文入库。
- 未登录用户不能访问受保护接口。
- 普通用户不能访问其他用户资源。
- token 具备过期和刷新机制。
- 管理员接口有明确权限保护。

## 7. 下一阶段衔接

完成认证安全后，下一步进入 `07 缓存 / Redis / 性能优化`。这时服务已经有真实业务形态，才更适合讨论热点数据、限流和吞吐优化。
